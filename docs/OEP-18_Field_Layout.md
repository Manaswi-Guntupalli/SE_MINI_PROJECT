# Current Release 1 Field Layout

Integrated implementation supplement to the initial `OEP-18_Field_Layout.xlsx`, dated 25 October 2026. **Pending team review.** The XLSX remains the original proposal; this version documents the actual field names and separate Response/Result storage chosen for the two integrated feature branches. Full relationships and naming crosswalk: [Domain model](DOMAIN_MODEL.md).

All collections have generated ObjectId `_id` and Mongoose UTC `createdAt`/`updatedAt`. ObjectIds serialize to 24 hexadecimal characters; Dates to ISO 8601. No user-supplied identity, deadline, status, owner or score is accepted by Student APIs. Fields below are persisted unless described as an API projection.

| Entity | Fields and BSON types | Required/default/constraints |
|---|---|---|
| User | name:String; email:String; passwordHash:String; role:String; active:Boolean | All required; trimmed name; unique trimmed lowercase valid email; bcrypt hash excluded from ordinary queries/API; role Student/Instructor/Admin; active defaults true. |
| Exam | title:String; description:String; instructorId:ObjectId→User; startTime:Date/null; duration:Number; status:String; questions:Array | Title nonblank; description defaults empty; authenticated owner required; start optional/null; duration finite and positive in minutes; Draft default or Published; Draft may be incomplete. |
| Question (embedded) | _id:ObjectId; questionText:String; options:Array; marks:Number | Nonblank text; generated ID unique within Exam; Draft options may be incomplete. Marks retained for UI compatibility, default/minimum 1; Release 1 evaluation maximum is the published question count (+1/0), not custom weighted marking. |
| Option (embedded) | _id:ObjectId; text:String; isCorrect:Boolean | Generated unique ID within Exam; text may be empty in Draft; correctness defaults false. On publication, at least two nonblank options and exactly one true flag per Question. |
| Attempt | studentId:ObjectId→User; examId:ObjectId→Exam; startedAt:Date; deadline:Date; status:String; submittedAt:Date/null; submissionReason:String/null; evaluationStatus:String; writeVersion:Number | Student/exam/start/deadline required and immutable; deadline later than start; status Active default or Submitted; Active has no submission metadata and Pending evaluation; Submitted requires timestamp/reason (Manual/Timeout); evaluation Pending default or Evaluated. writeVersion defaults 0, server-only serialization counter. |
| Response | attemptId:ObjectId→Attempt; questionId:ObjectId→embedded Question; selectedOptionId:ObjectId→embedded Option | All required; Attempt/question immutable. Service verifies Question belongs to Attempt's Exam and Option to that Question. Unique attempt/question pair. Missing record means unanswered. |
| Result | attemptId:ObjectId→Attempt; examId:ObjectId→Exam; studentId:ObjectId→User; score:Number; maximum:Number; status:String | All required; associations/score/maximum immutable. Unique attemptId. Nonnegative integers with score≤maximum; maximum equals published question count. status Evaluated. Association values derived from Attempt, not caller payload. |

Indexes: User unique email; Exam owner/createdAt and status/startTime; Attempt unique student/exam and status/deadline; Response unique attempt/question; Result unique attempt, student/createdAt and exam. Mongoose `__v` supports optimistic concurrency for Exam and Attempt. Standalone MongoDB cannot satisfy transactional persistence: use [replica-set setup](DATABASE_SETUP.md).

Student projections include question/option identifiers and text only. Correctness, bcrypt hashes and private session values are excluded. Result/attempt reads filter by current authenticated ownership; Instructor result reads require exam ownership. Proposed length conventions in the original XLSX are not silently asserted as implemented limits; the HTTP body cap and Admin password length limits are documented in the API contract.
