# Authentication and exam contract

Scope: #21, #23, #24, #33–#37. Sessions use `express-session` with MongoDB storage through `connect-mongo` outside isolated tests. The browser sends the HttpOnly `oep.sid` cookie with credentials. Cookies expire after two hours and use SameSite=Lax. NODE_ENV=production additionally sets Secure; production requires HTTPS. Set TRUST_PROXY=1 only behind a trusted, single-hop reverse proxy. CLIENT_ORIGIN is the exact credential-aware allowed browser origin. No wildcard origin is used.

POST `/api/auth/login` accepts `{email,password}`. Valid active accounts establish a newly regenerated and saved session; previous session IDs and CSRF tokens become invalid. GET `/api/auth/me` returns only public account fields. GET `/api/auth/csrf-token` returns the current session's random CSRF token. Every authenticated write requires this token in `X-CSRF-Token`. Browser writes from another Origin are rejected, including login. POST `/api/auth/logout` destroys the server session and expires the browser cookie; replay fails. Passwords are bcrypt hashes excluded from queries by default and never returned by account APIs.

Each protected request reloads the current account, active status and role. Admin does not inherit Instructor/Student operations. Account changes therefore apply to existing sessions on the next request.

## Instructor operations

All `/api/exams` operations require Instructor. GET `/mine` lists only the session owner's exams. POST `/` creates a Draft with `{title,description?,duration,startTime?}`. Owner and status always come from the server. Duration is a finite positive number in minutes (fractions allowed). Start is optional/null, otherwise an ISO timestamp with Z or an explicit offset; React converts local inputs to UTC and displays the browser timezone. Availability is an eligibility gate, not the student's countdown start.

GET, PUT and DELETE `/:id` require ownership. PUT accepts only title, description, duration and startTime. DELETE removes a Draft and its embedded questions/options. Published definitions cannot be edited or deleted. Question POST `/:id/questions`, PUT/DELETE `/:examId/questions/:questionId` require an owned Draft. Options are embedded `{text,isCorrect}` objects, so correctness always belongs to its question. Option IDs supplied in writes are rejected; replacement generates new embedded IDs. Nonblank question text is required. Draft option lists may be incomplete, including no correct answer. The UI permits adding/removing options and clearing/reselecting correctness.

POST `/:id/publish` requires a Draft with nonblank title, finite positive duration, at least one question, and for every question nonblank text, at least two nonblank options and exactly one correct option. Errors include validation details and leave the draft unchanged. Publication freezes definitions. Mongoose optimistic concurrency checks `__v` on every save; stale edits/publication fail with 409. Draft deletion conditions on ownership, Draft status and the same version, so it cannot delete a concurrently published exam. Published data is retained for historical attempts/results. GET `/:id/results` is restricted to the owning Instructor.

## Supporting role and publication handoffs

Student-only GET `/api/student/exams` lists all Published exams, including scheduled exams. Each safe projection includes `serverTime`, `attemptId`, `attemptStatus` (Not started/Active/Expired/Submitted), `canStart` and `canResume`. Drafts, questions and answer keys are excluded. POST `/api/student/exams/:id/start` revalidates publication/start eligibility, derives Student identity and atomically creates or resumes one attempt per student/exam. It returns `{attempt,responses,questions,serverTime}`. Concurrent starts preserve one deadline. Expired attempts finalize through Timeout and return 409 rather than restarting. GET `/api/student/attempts/:id` returns the same owned payload and finalizes an expired active attempt.

PUT `/api/student/attempts/:id/responses/:questionId` accepts `{selectedOptionId,expectedRevision}`. The expected revision starts at 0 and increments on each saved change. A stale revision returns 409; reload the protected attempt before retrying. Question/option membership, ownership, active status and database time strictly before deadline are checked transactionally. Student identity and deadlines in client payloads are never trusted.

POST `/api/student/attempts/:id/submit` accepts optional `{reason:"Manual"|"Timeout"}`. Early timeout is 409. Manual requests received after the deadline use Timeout; finalization is idempotent and serialized against answer writes. The returned attempt reports Submitted and evaluationStatus Pending/Evaluated. Submitted Pending evaluation is retried by the production expiry worker every `EXAM_EXPIRY_INTERVAL_MS` (default 5000 ms). Evaluation is isolated from durable finalization. The minimal OEP-39 handoff scores the saved immutable response set through the existing result persistence boundary. See [student acceptance](STUDENT_ACCEPTANCE.md) for batching and availability limits.

GET `/api/student/results` and `/api/student/results/:id` enforce Student ownership; Instructor GET `/api/exams/:id/results` requires exam ownership. Instructor result rows additionally include `student: {name,email}` (or null if the account is unavailable), joined only after exam ownership verification. The stored `studentId` remains unchanged. Student result responses do not include other account details. Results exclude answer keys.

Admin-only GET/POST `/api/admin/users` lists/provisions accounts. PATCH `/api/admin/users/:id` changes only a valid role or boolean active status. Creation requires a unique valid email and a password of at least 12 characters and at most 72 UTF-8 bytes, hashed with bcrypt; multibyte passwords cannot be silently truncated. No account deletion is provided; historical references remain intact. Admin cannot revoke their own access through this endpoint. Other roles cannot call these endpoints or set their own privileges.

For a new production database, set MONGO_URI, ADMIN_EMAIL, ADMIN_PASSWORD and optional ADMIN_NAME as process environment variables and run `node scripts/bootstrapAdmin.js` from server. The bootstrap refuses to run once an Admin exists and never prints a password. Clear ADMIN_PASSWORD from the environment afterward. Development seed credentials must not be used in deployment.

Invalid JSON/body shapes return safe 400 responses; oversized requests return 413. Protected operations reject missing sessions with 401, wrong roles/foreign Instructor ownership with 403, missing resources with 404, and stale writes with 409. No raw database errors are returned. Student foreign attempt/result reads and submissions use 404. Foreign answer writes use a generic 409 unavailable response and disclose no protected content.

## Shared persistence contract

The integrated persistence implementation uses the same User.email/User.active, Attempt.deadline and Result.maximum names as these APIs. Responses are in a separate collection; GET own-attempt returns a separate `responses` array. Attempt.status is Active/Submitted; evaluationStatus is independently Pending/Evaluated. Result retains derived studentId/examId, so protected result queries remain compatible. MongoDB transactions and `$$NOW` govern save/finalization/result writes through persistenceService; caller clocks do not override expiry. See [domain specification](DOMAIN_MODEL.md), [Field Layout](OEP-18_Field_Layout.md) and [replica-set setup](DATABASE_SETUP.md). The former deadlineAt/maximumScore/loginIdentifier/isActive variants are not parallel fields.
